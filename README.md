# Image Compressor

이미지 한 장을 업로드하고 원하는 최대 파일 용량 이하의 JPEG로 압축하여
다운로드할 수 있는 웹 서비스입니다.

## 프로젝트 목표

이 프로젝트의 가장 중요한 목표는 복잡한 기능을 빠르게 만드는 것이 아니라,
이미지 업로드부터 압축과 다운로드까지의 전체 데이터 흐름을 직접 이해하는
것입니다.

## 프로젝트 배경

온라인 자격증 제출이나 각종 서류 업로드 시 `500KB 이하`, `1MB 이하`와 같은
파일 크기 제한 때문에 이미지를 여러 번 수정해야 하는 경우가 많습니다.

이 서비스는 사용자가 원하는 최대 파일 용량을 입력하면 자동으로 이미지를
압축하여 이러한 불편을 해결하는 것을 목표로 합니다.

## 현재 구현 상태

현재 범위를 첫 MVP 완료 지점으로 봅니다.

- JPEG 또는 정적이며 투명 영역이 없는 PNG·WebP 한 장 입력
- 파일 선택과 Drag & Drop
- 최대 10MB 업로드
- 원본과 압축 결과 미리보기, 용량 및 해상도 표시
- 목표 용량(KB) 입력
- JPEG quality 60~95 범위에서 목표 이하인 가장 높은 품질 탐색
- PNG 입력은 사용자 승인 후에만 JPEG로 형식 변환
- quality 조절만으로 목표를 달성할 수 없으면 사용자 승인 후 비율을 유지하여
  해상도 축소
- 압축 결과 다운로드
- JPEG 및 PNG·WebP 입력 동작 자동 테스트

JPEG, PNG와 WebP또한 입력할 수 있지만 현재 출력 형식은 항상 JPEG입니다. 투명하거나
애니메이션이 있는 PNG·WebP는 지원하지 않습니다.

## 사용 흐름

1. 사용자가 JPEG, PNG 또는 WebP 이미지 한 장을 선택합니다.
2. 사용자가 원하는 최대 용량을 KB 단위의 양의 정수로 입력합니다.
3. 프론트엔드가 이미지와 목표 용량을 FastAPI 서버로 전송합니다.
4. PNG 입력은 JPEG 변환에 대한 사용자 승인을 먼저 받습니다.
5. 서버가 JPEG quality를 조절하여 목표 용량 이하의 결과를 찾습니다.
6. quality 60으로도 목표를 달성할 수 없으면 예상 축소 해상도를 안내합니다.
7. 사용자가 승인한 경우에만 비율을 유지하여 해상도를 줄입니다.
8. 압축 결과를 미리보고 JPEG 파일로 다운로드합니다.

업로드한 이미지는 저장하지 않으며 압축 요청 중 메모리에서만 처리합니다.

## 현재 범위에서 하지 않는 것

- 회원가입 및 로그인
- 데이터베이스와 압축 이력 저장
- 여러 이미지 동시 처리
- 투명 또는 애니메이션 PNG·WebP 입력
- PNG 또는 WebP 형식으로 결과 반환
- 이미지 편집 기능
- 클라우드 저장
- AI 기능

## 향후 방향

현재는 새로운 기능을 바로 추가하기보다 실제 사용자 피드백을 먼저 확인합니다.
일반적인 이미지 제출 용도에서 지원 형식과 10MB 입력 상한이 충분한지, PNG나
WebP가 JPEG로 바뀌는 것이 실제 불편으로 이어지는지가 주요 확인 대상입니다.

형식 관련 불편이 반복적으로 확인되면 다음 순서로 검토합니다.

1. 입력 형식을 유지하여 JPEG는 JPEG, PNG는 PNG, WebP는 WebP로 반환
2. 사용자가 JPEG, PNG 또는 WebP 중 원하는 출력 형식을 직접 선택

이는 확정된 개발 일정이 아니라 피드백 이후의 확장 후보입니다. PNG와 WebP는
JPEG와 압축 방식이 다르고 투명도와 애니메이션도 별도로 다뤄야 하므로, 실제
요구가 확인된 뒤 한 번에 하나의 작은 기능만 설계하고 구현합니다.

### 장기 학습 방향: AI 업스케일링

향후 AI 엔지니어링을 공부하기 위한 별도 확장 기능으로 이미지 업스케일링도
검토합니다. 단순히 픽셀 크기를 늘리는 일반 리사이즈가 아니라, AI 모델을 이용해
저해상도 이미지의 세부 표현을 보완하면서 더 큰 해상도의 이미지를 만드는
기능입니다.

업스케일링은 현재 압축 MVP의 다음 필수 기능은 아닙니다. 압축 기능과 목적이
다르고 모델 선택, 결과 품질, 처리 시간, 서버 메모리와 운영 비용을 별도로
학습하고 검증해야 하므로 장기 학습 과제로 둡니다. 구현할 때도 기존 압축 흐름에
한꺼번에 결합하지 않고 독립된 작은 단계부터 진행합니다.

## 기술 스택

- Frontend: React + TypeScript + Vite
- Backend: FastAPI
- Image Processing: Pillow
- Development: GitHub Codespaces

## 학습 목표

이 프로젝트를 통해 다음 내용을 이해하는 것을 목표로 합니다.

- 브라우저에서 파일을 업로드하는 과정
- `multipart/form-data` 요청
- FastAPI `UploadFile`
- Pillow를 이용한 이미지 처리
- JPEG 품질(quality)의 의미
- 파일 크기(Byte, KB, MB)
- 메모리에서 이미지 처리하기
- HTTP 파일 응답
- Blob 다운로드
- 프론트엔드와 백엔드의 요청·응답 흐름
